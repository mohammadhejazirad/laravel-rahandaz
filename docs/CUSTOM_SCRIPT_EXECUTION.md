# اجرای اسکریپت سفارشی

کاربر مورد اعتماد می‌تواند در طرح نسخه ۱ اسکریپت، نسخه، متغیر مجاز، timeout و زمان‌بندی را در پنل تعریف کند. UI و جدول تازه برای این کار در این برش ساخته نشده است. خود اجرا در `automation.custom_script` است.

قواعد اعمال‌شده:

- privilege عملیات `project` است.
- اگر درخواست از helper بیاید، نتیجه `ROOT_SCRIPT_FORBIDDEN` است.
- UID باید با `^[1-9][0-9]{0,8}$` جور باشد. صفر و تهی رد می‌شوند.
- مسیر نباید `..`، `/etc/` یا `/usr/` داشته باشد و باید فایل عادی داخل sandbox باشد، نه symlink.
- timeout از ۱ تا ۳۰۰ ثانیه است.
- apply از `systemd-run` با `CPUQuota=50%`، `MemoryMax=256M`، `TasksMax=64`، `RuntimeMaxSec` و `NoNewPrivileges=yes` استفاده می‌کند.
- محیط فرمان از `env -i` می‌گذرد.

این محدودیت‌ها جداسازی کامل نمی‌سازند. کد سفارشی غیرقابل اعتماد است و نسخه اول فقط پروژه مورد اعتماد را پوشش می‌دهد. اسکریپت سفارشی هرگز از helper به root ارتقا پیدا نمی‌کند.

زمان‌بندی نباید برای هر اسکریپت یک خط در `/etc/crontab` بسازد. `automation.refuse_cron` همین کار را با `CRON_WRITE_FORBIDDEN` می‌بندد. موعد باید در PostgreSQL بماند، Laravel Scheduler آن را به صف Redis بدهد، و worker اجرای محدود را شروع کند. آن سیم‌کشی در این برش به job engine وصل نشده است، چون دروازه اجرا بسته است.

متغیر محیط اضافه از لاراول فقط فهرست ثابت `LocalOperationProcess` را می‌پذیرد. کلیدی مثل `SECRET` رد می‌شود. راز پروژه فقط با مجوز صریح و فایل محدود باید به اسکریپت برسد. این مسیر تحویل راز هنوز ساخته نشده است.
