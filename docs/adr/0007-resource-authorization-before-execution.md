# ADR-0007 — مجوز منبع پیش از مشاهده و اجرای Job

تاریخ: ۲۰۲۶-۱۰-۱۸. وضعیت: پذیرفته برای برش پایهٔ authorization.

## مسئله

ProjectPolicy و queryهای کنترل‌پلین صرف عضویت workspace را کافی می‌دانند.
در worker نیز مجوز actor پس از enqueue بررسی نمی‌شود. بازکردن Gate در این وضعیت
می‌تواند IDOR و اجرای درخواست پس از لغو دسترسی ایجاد کند.

## تصمیم

مالک/مدیر همان workspace به پروژه‌های آن دسترسی دارند. Operator برای deploy به
grant صریح `deploy` روی پروژه نیاز دارد؛ Viewer حتی با این grant deploy نمی‌کند.
`view`، `deploy` و `operate` روی پروژه اجازه مشاهده metadata آن را می‌دهند؛
`manage_secrets` یا `restore` مجوز ضمنی مشاهده/استقرار نیستند. grant محیط به همهٔ
پروژه گسترش نمی‌یابد؛ پشتیبانی محدود به محیط باید در برش جدا افزوده شود.

یک query مشترک برای policy و فهرست پروژه و وابسته‌هایش استفاده می‌شود؛ شمارش و
pagination پس از scope است. تا طراحی permission مستقل log، Job/log فقط برای
مالک/مدیر همان workspace قابل مشاهده است؛ actor بودن مجوز نیست. این محدودیت موقت
قابلیت اپراتور را کاهش می‌دهد و باید در ادامه با grant مستقل برطرف شود.

worker هویت فعال و عضویت را از پایگاه دوباره می‌خواند. عملیات استقرار و سایت/گواهی محیط برای
اپراتور فقط با grant فعلی پروژه پذیرفته می‌شود. نوع عملیات ناشناخته برای اپراتور
رد می‌شود؛ مالک/مدیر همچنان Gate بسته را دور نمی‌زنند. لغو مجوز با خطای
`AUTHORIZATION_REVOKED` audit و terminal می‌شود و قفل دامنه آزاد می‌گردد.

هویت‌های سیستمی بی‌actor، grant محیط/سرویس/میزبان، دانلود artifact و secret به‌طور
خودکار از این تصمیم مجوز نمی‌گیرند. اجرای میزبان، installer و مرز UID تغییر نمی‌کنند.
UUIDv7 عمومی فعلی مطابق ADR-0004 حفظ می‌شود؛ ULID release فقط پس از طراحی مسیر
release جدا از شناسه مدل بررسی می‌شود، تغییر شناسه عمومی در این برش نداریم.

## پذیرش

تست واقعی PostgreSQL برای same/cross-workspace، فهرست و جزئیات، نقش Viewer، حذف
grant/عضویت، تعلیق actor، redelivery و شکست دامنه؛ هیچ تست fixture گواهی VM نیست.
