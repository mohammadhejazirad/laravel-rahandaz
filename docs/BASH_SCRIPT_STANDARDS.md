# استاندارد اسکریپت عملیات

هر wrapper یک shebang `#!/usr/bin/env bash`، `set -euo pipefail`، و یک نام عملیات ثابت دارد. ورودی کاربر نام تابع را انتخاب نمی‌کند.

`set -euo pipefail` به‌تنهایی کافی نیست. شکست داخل `$(...)` فقط همان subshell را می‌بندد. نتیجه JSON باید روی fd 3 نوشته شود که در `ops_init` از stdout اصلی کپی شده است. پاک‌سازی فایل موقت با trap است.

قواعد اجرایی:

- `eval`، ساخت shell از به‌هم چسباندن ورودی، `chmod 777` و `NOPASSWD: ALL` ممنوع است.
- فرمان خارجی از `ops_exec` می‌گذرد: نام allowlisted، مسیر مطلق، `env -i`.
- اگر `RAHANDAZ_OPS_BIN_DIR` باشد فقط همان دایرکتوری دیده می‌شود. این مسیر باید داخل sandbox باشد.
- شناسه‌ها، واحد systemd، بسته، دامنه، SHA و کاربر پروژه با عبارت منظم بسته چک می‌شوند.
- مسیر باید از `opsjson.py inside` رد شود. symlink و `..` رد می‌شوند.
- فایل رمز با `os.open` و پرچم‌های `O_CREAT|O_EXCL|O_NOFOLLOW` و حالت `0600` ساخته می‌شود. محتوا در argv نیست.
- قفل apply روی fd 9 با `flock -n` است. حذف دستی lock فایل apt ممنوع است و این موتور آن کار را نمی‌کند.
- timeout را dispatcher با `/usr/bin/timeout` اعمال می‌کند. اگر آن باینری نباشد، اسکریپت بدون timeout بیرونی اجرا می‌شود و این محدودیت باید در میزبان هدف جدا بررسی شود.

`opsjson.py` فقط کتابخانه استاندارد پایتون است. کلیدهای شبیه secret و متن `PRIVATE KEY` را در ورودی و خروجی رد می‌کند. `os-release` منبع نمی‌شود.

ابزارهای `shellcheck` و `shfmt` در محیط توسعه فعلی نصب نیستند. `bash -n` روی همه فایل‌های `.sh` این درخت اجرا شده است. ادعای عبور از shellcheck تا نصب و اجرای آن ابزار ثبت نمی‌شود.
