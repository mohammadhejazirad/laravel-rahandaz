# نصب نرم‌افزار و پایش منابع

کاتالوگ پنل بر اساس وب‌سرورها، زبان‌ها و runtimeها، دیتابیس‌ها، کش، ابزارهای کاربردی، آنتی‌ویروس‌ها و مدیریت پردازش دسته‌بندی می‌شود. تنها دسته‌های دارای نرم‌افزار نمایش داده می‌شوند. فهرست ثابت و نسخه‌دار در `infrastructure/operations/software/catalog.json` است؛ نام بسته، فرمان، URL یا مسیر دلخواه از مرورگر پذیرفته نمی‌شود.

مالک یا مدیر می‌تواند چند مورد را انتخاب، بازبینی و تأیید کند. دکمه از ثبت درخواست تا پایان واقعی در حالت در حال اجرا می‌ماند. بستن صفحه اجرای پس‌زمینه را متوقف نمی‌کند. نتیجهٔ هر مورد، مرحله، نسخه و خطای قابل اقدام جدا نمایش داده می‌شود؛ گزارش کامل در صفحهٔ عملیات است. پایان گروه شامل تعداد کل، موفق، ناموفق و اجرا‌نشده است. پیام Toast موفقیت فقط پس از تأیید نتیجهٔ واقعی می‌آید؛ ثبت درخواست موفقیت نصب نیست. گزارش ناموفق یا audit حذف نمی‌شود.

## رفتار بسته‌ها

- Nginx، PHP 8.4، PostgreSQL و Redis اصلی پنل: نصب تازه سرویس اصلی گم‌شده را جایگزین نمی‌کند و runtime پیش‌فرض یا تنظیمات پروژه‌ها را عوض نمی‌کند. PHP در کاتالوگ یک کارت است؛ مدال نسخه‌های ثابت ۸٫۲، ۸٫۳، ۸٫۴ و ۸٫۵ را نشان می‌دهد و انتخاب کاربر کلید کاتالوگ است، نه نام بسته یا نشانی. راه‌اندازی اولیه همچنان فقط چهار ابزار اختیاری را می‌پذیرد.
- صفحهٔ «نصب‌شده‌ها» موارد تأییدشده را با نسخهٔ گزارش‌شده نشان می‌دهد. دکمهٔ به‌روزرسانی یک job از نوع `software.upgrade` برای همان کلید می‌سازد و تا وضعیت پایانی همان دکمه در حال اجرا می‌ماند. به‌روزرسانی فقط بستهٔ همان شاخه را جلو می‌برد؛ برای PHP 8.4 یعنی بسته‌های `php8.4-*`، نه پرش به ۸٫۵ و نه حذف نسخهٔ دیگر. اگر نسخهٔ نصب‌شده آخرین کاندید مخزن باشد، نصب دوباره انجام نمی‌شود. PostgreSQL، MySQL، MariaDB و فایل‌های نسخه‌دار Node، MongoDB و Chrome از این دکمه به‌روز نمی‌شوند. نصب تازه همچنان `--no-upgrade` است. `update-alternatives` فقط اگر اسکریپت بسته هدف `/usr/bin/php` را عوض کرده باشد به هدف قبلی PHP برمی‌گردد.
- ابزارهای APT: htop، jq، FFmpeg، Unzip، Python/venv، MySQL، MariaDB، Memcached، ClamAV، Freshclam و Supervisor. نسخهٔ تمام وابستگی‌های جدید تثبیت و با امضاهای APT دریافت می‌شود. preference خصوصی نصب، نسخه‌های موجود را حفظ می‌کند؛ تنظیمات سراسری APT تغییر نمی‌کند. نیاز واقعی به ارتقا/حذف بستهٔ موجود، تداخل سرویس یا پورت اشغال‌شده باعث توقف همان مورد می‌شود.
- MySQL و MariaDB جایگزین خودکار یکدیگر نمی‌شوند. نصب نسخه و فعال‌بودن سرویس باید تأیید شود. ساخت پایگاه و کاربر پروژه، قابلیت جداگانه‌ای است.
- ClamAV بدون دیتابیس امضای تازه، برنامهٔ اسکن و آزمون شناسایی به معنی محافظت فعال نیست. Freshclam ممکن است توسط Ubuntu به‌عنوان وابستگی ClamAV نصب شود؛ کارت مستقل آن نصب یا بررسی سرویس به‌روزرسان امضا را انجام می‌دهد. این بخش ادعای اسکن خودکار سایت‌ها ندارد.
- Node.js LTS در مسیر نسخه‌دار مستقل نصب و Node/npm بررسی می‌شوند؛ Node پیش‌فرض سیستم و کد پروژه تغییر نمی‌کنند.
- MongoDB Community در مسیر نسخه‌دار مستقل نصب می‌شود. موتور با دادهٔ موقت، bind روی loopback و پاسخ واقعی hello آزمایش و سپس متوقف می‌شود. این نصب باینری است؛ سرویس دائمی، پایگاه یا پورت عمومی ساخته نمی‌شود.
- Chrome for Testing فقط با انتخاب صریح در کاتالوگ نصب می‌شود. نصب اولیه، راه‌اندازی اولیه و به‌روزرسانی پنل آن را دانلود یا نصب نمی‌کنند. checksum ثابت، استخراج امن، نسخه و رندر واقعی PNG/PDF با کاربر بدون امتیاز و sandbox بررسی می‌شوند. sandbox خاموش نمی‌شود. در Ubuntu 24.04 تنها profile مدیریت‌شدهٔ همان executable برای user namespace مجاز است؛ تنظیم عمومی AppArmor/sysctl تغییر نمی‌کند و فایل خارجی بازنویسی نمی‌شود.

مسیر اجرایی نسخه‌دار تنها از گزارش تأییدشده دریافت و در پنل با امکان کپی نمایش داده می‌شود. این مسیر را در تنظیمات کتابخانه یا متغیری که کد پروژه می‌خواند قرار دهید؛ نام متغیر محیطی به پروژه بستگی دارد. فایل `.env` پروژه خودکار ویرایش نمی‌شود. نصب MongoDB و Node به‌تنهایی راه‌اندازی پروژه نیست.

APT یا منبع رسمی ممکن است موقتاً در دسترس نباشد، درخواست را محدود کند یا دسترسی منطقه‌ای را رد کند. MongoDB پس از رد یا شکست منبع رسمی، می‌تواند همان آرشیو تغییرنیافته را از asset نسخه‌دار GitHub راه‌انداز دریافت کند؛ checksum رسمیِ پین‌شده در کاتالوگ امضاشده همچنان الزامی است. این فایل اختیاری در bootstrap دانلود نمی‌شود. دریافت آرشیو یک تلاش مجدد محدود دارد و همواره hash ثابت را بررسی می‌کند. محدودیت شبکه یا رد checksum با موفقیت جایگزین نمی‌شود. پس از رفع علت می‌توان درخواست تازه ساخت؛ نصب موجود دوباره بررسی می‌شود. پس از قطع نصب، وضعیت dpkg بررسی می‌شود و تعمیر تراکنش خارجی خودکار انجام نمی‌شود. timeout کل گروه پردازش را متوقف می‌کند تا فرزند دارای pipe باز، نصب را برای همیشه معطل نکند.

## خطاهای قابل پیگیری

فعال‌بودن انتخاب یک نرم‌افزار به معنی تضمین نصب آن روی هر وضعیت سیستم نیست. `PACKAGE_CONFLICT` یعنی نصب بدون ارتقا/حذف بسته‌های موجود قابل حل نیست؛ برای نمونهٔ VPS آزمایشی، Python/venv به patch جدید Python سیستم و MySQL به patch هم‌نسخهٔ libevent نیاز داشت. این به معنی نصب هم‌زمان خودکار MySQL و MariaDB نیست. به‌روزرسانی وابستگی‌های سیستم باید با برنامهٔ نگهداری و حفظ سرویس‌ها انجام شود؛ این قابلیت `apt upgrade` مخفی اجرا نمی‌کند.

`PACKAGE_SERVICE_FAILED` یعنی باینری وجود دارد ولی سرویس تأیید نشده است. در آزمون Freshclam سرور ایران، journal پاسخ 403 و مسدودی CDN رسمی امضاهای ClamAV را ثبت کرد. نصب مجدد پشت سر هم، خاموش‌کردن بررسی امضا یا استفاده از دیتابیس ناشناس راه‌حل معتبر نیست؛ منبع امضای معتبر و محدودیت شبکه باید بررسی شود. `DOWNLOAD_FAILED`/`DOWNLOAD_ACCESS_DENIED` مربوط به دریافت فایل‌اند؛ مسیر اجرایی موفق پیش از دریافت کامل، checksum و آزمون واقعی نمایش داده نمی‌شود. نتیجه و دلیل هر مورد در گزارش همان عملیات باقی می‌ماند و درخواست تازه پس از رفع علت ساخته می‌شود.

## پایش

هنگام بازبودن صفحه و اتصال اینترنت، منابع تقریباً هر سه ثانیه خوانده می‌شوند. CPU و نرخ دریافت/ارسال شبکه از اختلاف دو مشاهدهٔ واقعی محاسبه می‌شوند؛ نخستین نمونه نرخ ندارد. reset شمارنده، reboot و فاصلهٔ بیش از ۳۰ ثانیه نرخ نامعتبر را رد می‌کنند. شبکه مجموع رابط‌های قابل‌مقایسه بدون loopback است، نه اندازه‌گیری ترافیک اینترنت یک پروژه. حافظه بر پایهٔ `MemAvailable` است؛ دیسک مربوط به `/` است. نمودار حداکثر ۱۲۰ مشاهدهٔ واقعی دارد و از فاصلهٔ فاقد نمونه خط عبور نمی‌دهد. قطع شبکه و دادهٔ قدیمی صریح‌اند؛ مقدار نامعلوم صفر نیست.

خواندن منابع فقط از مسیرهای ثابت proc و API دیسک انجام می‌شود؛ HTTP shell یا فرمان privileged اجرا نمی‌کند. snapshot بین تب‌ها مشترک است؛ برای هر میزبان حداکثر یک نمونه در دقیقه در پایگاه ذخیره می‌شود. سلامت سرویس‌ها و هشدارها مشاهده‌های مستقل‌اند؛ تازه‌بودن منابع گواهی سلامت همهٔ سرویس‌ها نیست.

## مرز آزمون

Ubuntu 22.04 و 24.04 هدف این قابلیت‌اند؛ Ubuntu 26.04 فعلاً پیش از mutation رد می‌شود. آزمون کانتینر برای APT، آرشیو، نسخه و idempotency جای آزمون systemd، AppArmor، reboot یا VM نیست. گزارش اجرای واقعی و محدودیت‌ها باید در ماتریس عملیات ثبت شوند. همهٔ پیام‌ها و سؤال‌های Bash، شامل تغییرات آینده، باید انگلیسی و ASCII بمانند؛ فارسی مخصوص رابط وب و منابع ترجمه است.
