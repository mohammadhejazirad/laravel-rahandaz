## تلاش دوباره
برای deployment ناموفق باید علت اصلی، commit ثابت و توقف تلاش قبلی مشخص باشند. Retry نباید branch متحرک را دوباره resolve و commit تاریخی را عوض کند. عملیات متعارض یک محیط هم‌زمان اجرا نمی‌شوند.

## لغو
لغو پیش از اجرای worker می‌تواند وضعیت Job را cancelled کند. cancel_requested هنگام اجرای فرایند فقط درخواست است و اثبات توقف apt، migration یا build نیست. UI نباید توقف فوری اعلام کند.

## بازگشت
بازگشت کد و proxy با بازگرداندن schema/data تفاوت دارد. release قبلی باید موجود و سالم باشد و با دیتابیس جاری سازگار بماند. پس از migration مخرب تغییر symlink به‌تنهایی recovery نیست.

## وضعیت فعلی
مسیر rollback میزبان و سازگاری migration هنوز VM certification ندارند. از حذف release فعال یا آخرین نسخه سالم برای رفع خطا خودداری کنید. در recovery واقعی ابتدا وضعیت process، lease و داده را مشخص کنید.
